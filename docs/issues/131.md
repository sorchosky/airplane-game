# #131 QA3 · Soften the arms-down teaching prompt and remove its default panel

State: open · Labels: size:M, agent-ready, review:visual, milestone:M5 · https://github.com/sorchosky/airplane-game/issues/131

## Context

Batch 1, visual clutter and HUD clarity. Focused QA follow-up to #80, related to #79 and #82.

The owner's “Arms down to pause” message appears abruptly on an 80% dark rectangle. Current main's generic `Prompt.tsx` already uses `effect.textGlow` and an opacity transition, but `PauseTeaching.tsx` still uses `color.surfaceHud` and sets opacity immediately from the frame loop. This ticket closes that specific gap instead of repeating the full UI reskin.

## Goal

A gentle, panel-free default teaching prompt with readable text and hold progress, preserving the exact hands-free pause interaction.

## Acceptance criteria

- [ ] In the default appearance, remove the rectangle from PauseTeaching. Use tokenized text shadow/glow for text and an equivalent soft shadow for its SVG hold ring. No opaque replacement plate.
- [ ] Fade the complete prompt and ring in/out over a tokenized 400 ms ease, consistent with art-bible §8. Maintain the lower-third placement and TV body type.
- [ ] Keep the outgoing prompt mounted through fade-out. Prevent the normal control prompt and the teaching prompt from visibly overlapping during handoff.
- [ ] Progress uses the existing state machine's elapsed time. The visual fade must neither restart nor delay the five-second pause timer. Re-engaging arms cancels correctly, repeated drops do not leave a stale ring, and the tutorial still finishes under the existing once-per-flight semantics.
- [ ] Gate the teaching prompt to Camera mode or the explicit pose/replay test path. It must not appear or gesture-pause in normal Mouse/Touch play.
- [ ] Respect reduced motion with immediate visibility changes and no animated entrance. Pause progress and operation remain functional.
- [ ] Preserve the explicit high-contrast accessibility mode. If it requires a panel, apply that only in the opted-in mode. Default appearance remains panel-free. Coordinate with existing #82 settings rather than adding another preference.
- [ ] Validate text and progress-ring legibility over bright clouds/snow, grass, dark terrain, and night sky. Use rendered background samples for WCAG AA text and applicable 3:1 non-text contrast checks. Do not claim a token-only foreground comparison proves a soft shadow passes over every scene.
- [ ] Keep styling tokenized, copy centralized, and per-frame progress updates outside React state. Add behavioral regression coverage for visibility, mode gating, cancel/retry, pause, and reduced motion.
