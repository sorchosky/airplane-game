# #226 HUD prompt matches the control mode: no "Spread your arms" outside Motion

State: open · Labels: agent-ready, size:S, milestone:M5 · https://github.com/sorchosky/airplane-game/issues/226

## Context
In Touch and Mouse modes the HUD shows "Spread your arms to fly" with the wing glyph whenever the
plane is on autopilot. Root cause: Keyboard, Mouse and Touch all write `source: 'keyboard'`
(`src/input/InputSource.tsx`), and `presence()` in `src/app/controlStore.ts` returns `'in-frame'`
for that source, which `PROMPT_FOR` maps to `'spread-arms'`. Keyboard mode shows it too, and
`tests/e2e/controlState.spec.ts` currently asserts that text.

## Goal
Each control mode shows only a prompt that matches how the player actually steers.

## Acceptance criteria
- [ ] Motion (pose and replay) keeps today's prompts exactly.
- [ ] Touch: no arms prompt. While on autopilot, after the existing `promptDelayMs`, show "Touch
      and drag to steer" with a thumb glyph, once per flight. After the first touch it never shows
      again that flight.
- [ ] Mouse: same rule, "Move the mouse to steer".
- [ ] Keyboard (dev): "Press Space to fly".
- [ ] New strings live in `src/ui/copy.ts`. The prompt type gains the new values. The wing glyph
      shows only for `spread-arms`.
- [ ] Unit test for the prompt picked per mode and source. Update `controlState.spec.ts`. Add an
      e2e case for Touch mode asserting `data-prompt` is never `spread-arms`.
