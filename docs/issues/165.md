# #165 Day cycle starts at the player's local time

State: open · Labels: agent-ready, size:S, milestone:M5 · https://github.com/sorchosky/airplane-game/issues/165

Part of #162.

## Context

The in-game clock (#94, `src/world/gameClock.ts`, `src/world/clockStore.ts`) opens a first flight at 07:00 and resumes later flights from a time saved in `localStorage`. The owner wants the game's light to match the room the player is in, with no jump from a fixed 07:00 to the real time (owner decision 2026-10-01). The title shows a fixed time that maps to the player's local time. When flight begins, the clock advances from that same minute at one day per 300 real seconds.

## Goal

Each page load sets the clock to the device's local time, holds it through the title and front door, and starts the existing cycle from that minute when flight begins.

## Acceptance criteria

- [ ] A pure `localClockMinutes(date: Date)` returns minutes since local midnight from the device's time zone, with unit tests across several fixed dates and offsets, including a daylight-saving change.
- [ ] `resolveClockConfig` uses local time as the start for every session. The saved-time resume and the 07:00 first-flight default are removed, along with the `localStorage` writes and reads. Stale saved values are ignored and cleared.
- [ ] `?time=HH:MM`, `?tod=<phase>`, `?cycle=<s>` and `?shot=` behave as today and take priority over local time.
- [ ] The clock is set once per page load, before the world's first frame, so the title already shows the local-time light. (`TitleSky`, the boot poster, uses its own baked colours and is unaffected.)
- [ ] The clock holds still in every state except `flying` (today's rule). Flight begins from exactly the held minute. A unit test asserts the first flying tick advances from the title's minute with no discontinuity.
- [ ] Quit to title holds the current in-game time (no snap back to local time, which would be a jump). A new page load reads local time again.
- [ ] The `?debug` overlay shows the in-game time as `HH:MM`. Nothing player-facing shows digits once #166 lands.
- [ ] Decision file `docs/decisions/2026-10-01-<issue#>-local-time-start.md` superseding #94's resume and 07:00 rules.
- [ ] Existing clock tests updated. No clock behaviour change beyond the start time.
