# #215 World goes blank for good when a new WebGL context can't be created

State: open · Labels: bug · https://github.com/sorchosky/airplane-game/issues/215

## Problem

In flight, the world can vanish and never come back. The HUD and prompts stay, but behind them is only the CSS sky fallback (`TITLE_SKY_FALLBACK`). The sim stops too, so the plane is frozen.

This happened again after #213, which fixed the frame-delta jump when the 30 fps cap turns on.

## Cause

After a WebGL context loss, `FlightScene` remounts the canvas. If the browser refuses the new context (common on a phone that shares the GPU with the pose model), `WebGLRenderer` throws. `WorldLayer`'s `WorldBoundary` catches that and renders `null` permanently.

Repro in headless Chromium: force `WEBGL_lose_context.loseContext()` mid-flight and make the next `getContext('webgl2')` return `null`. The world never returns.

## Acceptance criteria

- [ ] A canvas whose renderer can't be created is retried instead of dropped
- [ ] A single context loss still remounts at once
- [ ] Repeated failures back off, and a world that never drew stops retrying so no-WebGL devices keep the poster
- [ ] One context loss bumps the context generation once
- [ ] An e2e test covers a refused context and fails without the fix
