# #130 QA2 · Move the in-flight Pause action to the bottom right

State: open · Labels: agent-ready, size:S, review:visual, milestone:M5 · https://github.com/sorchosky/airplane-game/issues/130

## Context

Batch 1, visual clutter and HUD clarity. Follow-up to #109/#110. The touch Pause action occupies the same top-right area as the in-game clock and misleadingly says “Paused” while flying.

In current main, `InputSource.tsx` positions the button with `top: space.md` and reuses `copy.pause.title`, whose value is “Paused”. This is an action-label and layout defect, not evidence that flight is actually paused.

### QA photo references

All seven photos show “Paused” over the top-right clock. `IMG_0270.jpeg` is the clearest dawn example. `IMG_0272.jpeg` shows the overlap while steering with the touch joystick. Debug pose panels and Record pose occupy the bottom right in these captures and must be considered during placement.

Photo filenames refer to the original screenshots supplied with the owner's September 28 QA, reviewed September 29. They are reference identifiers, not repository paths or embedded GitHub attachments.

## Goal

An accurately labeled, reachable Pause action in the bottom-right safe area, with the clock unobstructed.

## Acceptance criteria

- [ ] While flying in Touch mode, label the action “Pause”, with the same accessible name. Add a dedicated string in `src/ui/copy.ts`. Preserve “Paused” for the actual paused-state heading.
- [ ] Position the button at bottom right with existing 8pt spacing tokens plus device safe-area insets. Keep the clock at top right.
- [ ] Preserve the existing minimum 48 × 48 CSS px touch target and TV body type. Provide default, focus-visible, and pressed states consistent with existing UI tokens.
- [ ] Button pointer events never spawn or move the floating joystick and never write steering input. Tapping once opens the existing pause menu once. Resume still returns to flight.
- [ ] Show the action only in its existing applicable flying control mode. Do not add required touch interactions to Camera mode or change keyboard Esc behavior.
- [ ] No overlap with the clock, captions, portrait/orientation UI, or device safe area at landscape phone, iPad, and desktop test sizes.
- [ ] With `?debug`, reserve space for the action by minimally offsetting the bottom-right pose recorder/readout where needed. Both Pause and Record pose remain reachable. No debug-panel redesign.
- [ ] Add a touch e2e regression for label, bounding-box non-overlap, click behavior, and joystick exclusion. Include screenshots with debug both off and on.

## Out of scope

Pause menu redesign, pause gesture timing, control selection, joystick mapping, and the teaching-prompt visual treatment in QA3.

## Depends on

None. Touch controls and the clock are present on inspected main.

## Likely files

`src/input/InputSource.tsx`, `src/input/TouchControls.tsx` or its joystick event handling, `src/ui/copy.ts`, `src/styles/tokens.*` if a new semantic token is needed, bottom-right debug UI, `tests/e2e/`.

## Verification

- At 844 × 390, 1024 × 768, and 1920 × 1080, enter Touch mode and inspect the layout with debug on/off. Include a safe-area inset case.
- Tap Pause, resume, drag the joystick near but outside the button, and tap the button during a held touch. No stale or second steering pointer remains.
- Verify the actual paused heading is still “Paused” and the clock stays readable.
- `npm run check` and the touch e2e spec pass locally and in CI.
