# #151 [Epic] Front door · One continuous scene from title to flight

State: open · Labels: epic, review:visual, milestone:M5 · https://github.com/sorchosky/airplane-game/issues/151

## Goal

Replace the separate title, control select and calibrate screens with one continuous scene over the live world: an editorial masthead over a flyby, a control choice in viewfinder frames, a calibration frame that grows out of the Motion choice, and a camera glide into flight. Coordination issue, not an implementation ticket.

## Context

Owner QA on 2026-10-01 (iPhone screenshots of the title, control select and portrait prompt) judged all three below the AAA bar. The owner supplied a control-choice mockup (corner-mark frames, a hairline T-pose figure labelled MOTION, a touch hand labelled TOUCH, header "CHOOSE YOUR CONTROL SETUP") and asked for the whole flow to feel like one scene that progresses with each choice. Decisions are recorded by the first child ticket.

## Beats

| Beat | Game state | On screen |
|---|---|---|
| 0 Poster | `title` booting | `TitleSky` still |
| 1 Masthead | `title` | Flyby, masthead left third |
| 2 Choose | `select` | Blurred world, running head, header, two viewfinder frames |
| 3a Position | `permission`, `calibrate` | Motion frame becomes the calibration frame, figure becomes the target |
| 3b Touch | `select` → `flying` | Tap ring expands as blur clears |
| 4 Flight | `wings`, `flying` | Chase camera, corner preview on the Motion path |

## Boundaries

- WebGL2 only, one WebGL context after boot.
- No change to the flight model, gesture interpreter, calibration math or the `ControlInput` contract.
- Game state machine unchanged. The stage maps states to beats.
- Palette B and existing tokens. New tokens only where a child names them.
- Every beat respects `prefers-reduced-motion`.
