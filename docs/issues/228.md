# #228 Warm caption ignores a steady 30 fps cap

State: open · Labels: milestone:M4, agent-ready, size:S · https://github.com/sorchosky/airplane-game/issues/228

## Context
Existing work: #199 (owner runs a diagnostic on the phone) and #203 (phone retest). The code
already shows one cause for certain, no phone needed. The ladder reaches post tier `low` and then
adds the 30 fps cap. `stepThermalWatch` in `src/app/robustness.ts` fires when tier is `low` and
p95 > 33 ms for 10 s. A capped frame is 33.3 ms by design, so every phone that reaches the cap
shows "Your phone is getting warm" about 10 s later. `?cast` starts capped, so cast mode is the
worst case. This is cause 1 in #199.

## Goal
The caption shows only when frames are slower than the active cap allows, sustained, and never in
the first minutes of play.

## Acceptance criteria
- [ ] The threshold is cap-aware: `1000 / capFps × 1.2` when capped (40 ms at 30 fps), the current
      33 ms otherwise. Use `CAST_GOVERNOR_PARAMS.budgetMs` if that keeps one source of truth.
- [ ] It fires only on the governor's bottom rung, so the ladder has had its chance first.
- [ ] Sustain rises to 30 s, and nothing fires in the first 120 s of a flight.
- [ ] The watch uses the governor's settle and stall filtering (`SETTLE_TIME`, `STALL_MS` in
      `QualityGovernor.tsx`), cause 3 in #199.
- [ ] `robustness.test.ts` covers a steady 33.3 ms capped run (never fires), a 45 ms capped run on
      the bottom rung (fires after 30 s), and the 120 s grace.
- [ ] Comment on #199 that cause 1 and cause 3 are fixed here. #199 stays open for the phone run
      to check nothing else remains.
