# #164 Stars fade in by brightness with the sun

State: open · Labels: agent-ready, size:S, review:visual, milestone:M5 · https://github.com/sorchosky/airplane-game/issues/164

Part of #162.

## Context

`src/world/Stars.tsx` draws one point cloud whose alpha is `atmoNight`, a value driven by the day-cycle colour keys (night 22:00 to 03:30, morning 07:00). At 05:30 the sky is already daylight blue while `atmoNight` is still well above zero, so stars show on a blue sky (owner QA, 2026-10-01). The owner wants stars to fade in slowly at night and out at daybreak.

## Goal

Stars appear one by one as the sky darkens, brightest first, and leave the same way at dawn, keyed to how dark the sky actually is.

## Acceptance criteria

- [ ] Star visibility is driven by sun elevation, not `atmoNight`. A pure function `starVisibility(sunElevation, magnitude)` returns 0..1, with unit tests.
- [ ] Each star has a brightness rank. The brightest start fading in when the sun is 2° below the horizon. The faintest finish fading in at 14° below. Dawn runs the same curve in reverse. Each star's own fade takes at least 20 in-game minutes (at the default cycle, roughly 4 real seconds).
- [ ] No star is visible while the sun is above the horizon (test).
- [ ] Optional subtle twinkle (±10% alpha, per-star phase, 2 to 5 s period), off under reduced motion.
- [ ] Still one draw call. Sun elevation comes from the existing atmosphere uniforms (add one if needed, shared with every material, no per-frame allocation).
- [ ] Screenshots at `?time=` 18:30, 19:30, 20:30, 22:00, 05:00, 05:30, 06:30 with `?shot=away-from-sun`.

## Out of scope

Moon rendering. Star layout or count.
